KV Cache · 레슨 0002 · 약 10분

생성 한 스텝에서 무엇을 다시 쓰고 무엇을 버리나

Q·K·V 역할이 흐릿하면 이전 레슨 0001 · Q·K·V와 masked attention부터 보세요. LLM은 토큰을 하나씩 만듭니다. 그때 같은 계산이 매번 반복된다는 걸 직접 버튼으로 확인합니다.

이 레슨이 끝나면

t번째 토큰을 만들 때 새로 계산하는 것, 캐시에서 꺼내 쓰는 것, 버리는 것을 한 문장씩 말할 수 있습니다.

1 · 생성은 루프다

토큰 하나 만들고, 그걸 다시 입력에 붙인다

"나는 오늘"이 들어오면 모델은 다음 토큰 "점심으로"를 냅니다. 그다음엔 "나는 오늘 점심으로" 전체가 다시 입력이 됩니다. 이렇게 한 번에 하나씩 만드는 걸 autoregressive 생성이라고 합니다.

"To predict the 1000th token, the model requires information from the previous 999 tokens." — Hugging Face Transformers, Caching

문제: 1001번째를 만들 때도 앞의 999개 정보가 또 필요합니다. 같은 걸 매번 다시 계산하면 낭비입니다.

2 · 한 스텝에서 attention이 하는 일

지금 토큰의 Q가 과거 모든 토큰의 K를 훑는다

Attention 논문에서 본 그대로입니다. 지금 토큰의 Q(질문)를 모든 토큰의 K(색인)와 내적해서 점수를 내고, 그 점수로 V(내용)를 섞습니다.

Attention( q_t , [k_1 … k_(t-1), k_t] , [v_1 … v_(t-1), v_t] )

백엔드로 치면 Q는 검색어, K는 인덱스, V는 실제 레코드입니다. 새 검색어는 하나뿐이고, 인덱스와 레코드는 과거 것이 전부 필요합니다.

필요한 것: 지금 토큰의 Q 1개 + 과거·현재 모든 토큰의 K와 V.

3 · 왜 저장해도 되나

과거 토큰의 K·V는 나중에 바뀌지 않는다

GPT 계열은 causal mask를 씁니다. 각 토큰은 자기보다 앞만 볼 수 있습니다. 그래서 "오늘"의 K·V는 "나는 오늘"만 보고 정해지고, 뒤에 무슨 토큰이 오든 같습니다.

"Once a token is processed, its representation never changes with respect to future tokens, which means K_past and V_past can be cached and reused." — Hugging Face Transformers, Caching

직접 해 보세요. 다음 토큰 생성을 여러 번 누르고, 모드를 "캐시 없음"으로 바꿔 빨간 테두리(다시 계산하는 행)를 보세요.

캐시가 있으면 매 스텝 새 행 1개만 계산합니다. 없으면 1+2+3+…로 쌓여서 길이의 제곱으로 늘어납니다.

5 · 층마다 따로

캐시는 층 수만큼 있다

층마다 K·V를 만드는 행렬이 따로 있어서, 같은 토큰이라도 층마다 다른 K·V가 나옵니다. 그래서 캐시는 층별 목록입니다. Hugging Face 구현에서 층 하나의 캐시 모양은 다음과 같습니다.

cache.layers[i].keys   : [batch, num_heads, seq_len, head_dim]
cache.layers[i].values : [batch, num_heads, seq_len, head_dim]
# 새 토큰이 오면 seq_len 방향으로 붙인다 (torch.cat, dim=-2)

대가: 계산은 줄지만 메모리는 토큰마다 늘어납니다. 얼마나 늘어나는지가 다음 레슨입니다.

헷갈리기 쉬운 것

KV Cache ≠ API 프롬프트 캐싱 할인. KV Cache는 요청 하나 안에서 이전 토큰의 K·V를 다시 계산하지 않으려는 것입니다. API 할인은 요청 사이에서 같은 앞부분(시스템 프롬프트 등)의 K·V를 재사용하는 prefix caching입니다. 둘 다 K·V를 저장하지만 범위가 다릅니다. prefix caching은 이후 레슨에서 다룹니다.
