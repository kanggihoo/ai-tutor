# C7. 총정리: 절대 일어나면 안 되는 일 8가지

지금 하는 일: C1~C6에서 본 방어가 D-14의 금지 목록 8가지와 어떻게 연결되는지 정리하고, 사용자님이 위협 모델 초안을 직접 쓰는 레슨입니다.

## 연결표

각 금지 항목을 어느 레슨이 막는지 보는 용도라서 표를 씁니다.

| # | 일어나면 안 되는 일 | 막는 곳 |
|---|---|---|
| (1) | 포크 PR이나 같은 저장소의 `main`이 아닌 branch의 코드가 시크릿에 닿거나 쓰기 권한으로 실행됨 | C2 |
| (2) | 비밀이나 내부 토폴로지가 공개 로그, 저장소, 이미지에 남음 | C6 |
| (3) | 출처가 검증되지 않은 이미지가 릴리스로 기록됨 | C3 |
| (4) | 같은 sha 태그를 다른 내용으로 게시하거나, 배포가 태그로 이미지를 고름 | C2 |
| (5) | 필수 체크가 실패나 건너뜀인데 병합됨 | C1 |
| (6) | 승인 없이 prod에 배포됨 | C4 |
| (7) | dev 자격으로 prod에 접근함 | C4, C5 |
| (8) | helper가 관리자가 설치한 것 외의 compose나 스크립트를 실행함 | C4 |

## 알면서 남겨 둔 구멍

- 1인 운영이라 `.github/**` 변경과 prod 승인을 독립적으로 검토할 사람이 없습니다. (C1, C4)
- 환경별 SSH 키와 tailnet 접근이 함께 유출되면 출처가 유효한 이미지를 임의로 고를 수 있습니다. (C4)
- 악성으로 판명된 `main` 커밋을 차단하는 경로는 배포 반복 전에 정합니다. (C3)
- 출처 검증은 GitHub와 Sigstore가 살아 있어야 합니다. (C3)
- 같은 서버의 Jenkins가 root급이고 폐기 전까지 남습니다. (C5)
- 로그 스캐너가 없습니다. (C6)
