# 레슨 02 · 소유권 (2026-10-28)

## 이론 요약
1. 값에는 주인(소유자)이 하나. `let b = a;`(`String` 등 힙 데이터)는 **move**라 `a`는 더 못 쓴다(E0382).
2. `i32` 같은 단순 타입은 `Copy`라 대입해도 원본이 살아 있다.
3. `.clone()`은 힙 데이터까지 복사한다. 함수가 읽기만 하면 복사 대신 `&`로 **빌린다**. `&String`과 `String`은 다른 타입이라 정의·호출 양쪽에 `&`를 쓴다.

```rust
fn count_chars(text: &String) -> usize { text.chars().count() }
let n = count_chars(&msg);   // msg는 계속 쓸 수 있다
```
실제 코드에선 에러를 피하려고 붙인 `.clone()`이 자주 보이니, 정말 필요한지 의심한다.

## 퀴즈
| # | 코드 | 정답 |
|---|---|---|
| Q1 | `String` move 후 사용 | E0382 |
| Q2 | `i32` 대입 후 둘 다 출력 | 컴파일됨, `5 5` |
| Q3 | `.clone()` 전달 | 컴파일됨, `KIM!`/`kim 3` |
| 복습 | `let b = a;` + `i32` 복사 | `hi 5 5` |
| 복습 | `n * 2;`로 끝나는 함수 | E0308 (`;` 제거) |

## 실전
- `lab/src/bin/02_fix_p1.rs` (고치기): `count_chars(msg)` 후 `msg` 사용 → E0382. A `msg.clone()`, B `&String`+`&msg`. B가 낫다(읽기만 하므로). 호출부 `&`만 빼면 E0308.
- `lab/src/bin/02_review_p2.rs` (리뷰): 불필요한 `clone` 3개(12·13·`copy`). 함수를 `&String`으로 받고 `user`를 그대로 출력. 사용자가 시그니처·호출부는 고쳤고 마지막 `copy`는 "했다"고 보고(튜터 미확인).
- 원래 문제는 위 풀이 전 상태(함수가 `String`을 받고 `user.clone()` 3번).

## 틀린 것·약점
- `;` 반환 문제에서 "컴파일되나요?"에 답하지 않고 고치는 법부터 답함(2회).
- `&`가 정의·호출 양쪽에 필요한 이유를 질문으로 확인.
