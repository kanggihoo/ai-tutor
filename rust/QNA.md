## 타입·구조체·열거형

### Q. Rust에서 `let`은 뭘 의미하나?
- 2026-10-27 · 레슨 01 · 복습
- 답: "이 이름을 이 값에 묶는다(binding)"는 선언이다. `let`만 쓰면 불변 바인딩이라 다시 대입할 수 없고, 바꾸려면 `let mut`이다. 불변이 기본이라 "어디서 값이 바뀌는지"가 `mut` 표시로 드러난다(C++의 `const`가 기본인 셈).
- 한 줄 요약: `let` = 불변 바인딩 선언, 바꾸려면 `mut`.

### Q. `let x = 5; let x = x * 2;`처럼 같은 이름을 다시 선언하면 어떻게 되나?
- 2026-10-27 · 레슨 01 · 복습
- 답: 에러가 아니라 **섀도잉**이다. 두 번째 `let`이 값이 10인 새 변수 `x`를 만들고, 이후에는 이 이름이 새 변수를 가리킨다(옛 `x`는 접근만 못 할 뿐 대입으로 바뀐 게 아니다). 타입도 바꿀 수 있다. 안쪽 `{}` 블록의 섀도잉은 블록이 끝나면 사라지고 바깥 `x`가 다시 보인다. 같은 스코프 재선언은 Java·C++·JS(`let`)에서는 에러라 낯설다. 실제로는 `let s = s.trim(); let n: i32 = s.parse()?;`처럼 변환 단계를 이어 쓸 때 자주 보인다.
- 한 줄 요약: 섀도잉 = 값 변경이 아니라 같은 이름의 새 변수.

### Q. 변수의 타입을 바꾸는 것도 `mut`로 해야 가능한가?
- 2026-10-27 · 레슨 01 · 복습
- 답: 아니다. `mut`는 **같은 타입 안에서** 값만 바꾼다. `let mut x = 5; x = "hi";`는 컴파일 에러다. 타입을 바꾸려면 `let x = "hi";`처럼 `let`을 다시 써서 새 변수(섀도잉)를 만든다.
- 한 줄 요약: `mut` = 값 변경(타입 고정), 타입 변경 = `let` 섀도잉.

### Q. 마지막 줄에 `;` 없이 `n * 2`만 쓰면 `return n * 2;`와 같은가?
- 2026-10-27 · 레슨 01 · 복습
- 답: 결과는 같다. 마지막 표현식이 함수의 반환값이다. `return`은 중간에 일찍 빠져나올 때 쓴다. `;`를 붙이면 값이 버려지고 `()`가 되어 반환 타입 불일치 에러가 난다. `if`/`match`/블록도 값을 내는 표현식이다.
- 한 줄 요약: 마지막 줄 `;` 없음 = 반환, `;` 있음 = 값 버림.

## 모듈·Cargo·크레이트

### Q. `cargo run`은 C++처럼 컴파일해서 실행 파일을 만들고 실행하는 것까지인가?
- 2026-10-27 · 레슨 01 · 복습
- 답: 맞다. rustc가 소스를 기계어로 컴파일(미리 컴파일, AOT)해 `target/debug/lab.exe`를 만들고, cargo가 그걸 실행한다. 의존성 크레이트도 같이 컴파일된다. 소스가 안 바뀌면 재컴파일 없이 바로 실행한다.
- 한 줄 요약: `cargo run` = 컴파일(`target/`에 생성) + 실행.

### Q. Rust 패키지는 전역에 설치되나? `target/`은 빌드 결과물인가?
- 2026-10-27 · 레슨 01 · 복습
- 답: 절반만 맞다. 다운로드한 크레이트 **소스**는 전역 캐시(`~/.cargo/registry`)에 한 번 받아 여러 프로젝트가 공유한다. 하지만 **어떤 버전을 쓸지**는 프로젝트의 `Cargo.toml`/`Cargo.lock`이 정하고, 컴파일 결과는 프로젝트별 `target/`에 쌓인다. 그래서 가상환경이 필요 없다. 전역에 깔리는 건 `cargo install`로 설치한 도구(`~/.cargo/bin`)다. `target/`은 빌드 결과물이 맞고 git에 올리지 않는다.
- 한 줄 요약: 소스 캐시는 전역·버전과 빌드는 프로젝트별, `target/`은 `.venv`가 아니라 빌드 산출물.

### Q. Cargo.toml은 uv의 pyproject.toml과 비슷한가?
- 2026-10-27 · 레슨 01 전 · 복습
- 답: 거의 같은 역할이다. `[package]`≈`[project]`, `[dependencies]`≈`dependencies`, `[dev-dependencies]`≈dev 그룹, `features`≈extras, `Cargo.lock`≈`uv.lock`, crates.io≈PyPI. 명령도 `cargo add/remove/run/tree`≈`uv add/remove/run/tree`, `cargo install`≈`uv tool install`, `cargo fmt`/`clippy`≈`ruff format`/`ruff check`. 차이: Rust는 컴파일 언어라 `.venv` 대신 `target/`에 빌드 결과가 쌓이고, 가상환경 없이 의존성이 프로젝트와 함께 컴파일된다. 툴체인 버전은 rustup(`rust-toolchain.toml`)이 맡는다(uv의 `.python-version`과 비슷).
- 한 줄 요약: Cargo = uv + ruff + 빌드 도구를 합친 것.

### Q. clippy는 뭘 하나? formatter인가?
- 2026-10-27 · 레슨 01 · 복습
- 답: formatter가 아니라 **린터**다(`ruff check`와 비슷). 코드를 고치지 않고 "더 나은 방식이 있다"고 경고만 한다(예: `count = count + 1` → `count += 1`). 코드 모양을 정리하는 formatter는 `cargo fmt`다. 컴파일러 경고(`unused_*`)는 rustc가, `clippy::*` 경고는 clippy가 낸다.
- 한 줄 요약: `cargo clippy` = 린터(조언), `cargo fmt` = 포매터(모양 정리).

### Q. `target/debug`와 `target/release`는 뭐가 다른가?
- 2026-10-27 · 레슨 01 · 복습
- 답: 같은 코드를 다른 설정(프로필)으로 빌드한 결과가 각각 들어간다. `debug`(기본, `cargo run`/`build`)는 최적화 없이 디버그 정보를 넣어 컴파일이 빠르고 실행은 느리다. 정수 오버플로 시 패닉도 이때 난다. `release`(`--release`)는 최적화해서 컴파일은 느리지만 실행이 훨씬 빠르다. `cargo run --release`는 release로 빌드하고 **실행까지** 한다(빌드만은 `cargo build --release`).
- 한 줄 요약: 개발 중엔 debug, 배포·성능 측정엔 release. `run`=빌드+실행, `build`=빌드만.

### Q. `.exe`는 Windows라서 생긴 건가? `.d`, `.pdb`도 실행 파일인가?
- 2026-10-27 · 레슨 01 · 복습
- 답: Rust 소스는 플랫폼과 무관하지만 **빌드 결과는 빌드한 OS용**이다. Windows는 `.exe`, Mac/Linux는 확장자 없는 파일이 생긴다(다른 OS용은 `--target`으로 크로스 컴파일). 실행 파일은 `.exe` 하나다. `.pdb`는 디버거용 심볼 정보, `.d`는 소스 파일 의존 목록(텍스트)이라 실행하지 않는다.
- 한 줄 요약: 실행 파일은 `.exe`뿐, 나머지는 빌드 부산물.

### Q. `::`는 뭔가? 외부 패키지를 쓸 때 많이 보이던데
- 2026-10-27 · 레슨 06 예고 · 복습
- 답: 경로 구분자다. 모듈·타입의 경로는 `::`, 값의 메서드는 `.`으로 나눠 쓴다. `std::fs::read_to_string("a.txt")`는 표준 라이브러리 `fs` 모듈의 함수, `serde_json::from_str(s)`는 외부 크레이트의 함수, `String::new()`는 타입에 붙은 함수(Python의 클래스 메서드와 비슷)다. 매번 길게 쓰기 싫으면 `use serde_json::Value;`처럼 가져온다(Python의 `from ... import`).
- 한 줄 요약: `::`는 "어디에 있는 무엇"(경로), `.`은 "이 값의 메서드".
